# Internationalization Routing

- `src/lib/i18n/locales.ts` is the single source of truth for supported locales, the default locale, document language, Open Graph locale, and locale names. `astro.config.mjs` imports it rather than repeating the values.
- The supported locales are `fr` and `en`. French is the default and every locale is prefixed.
- Astro i18n owns locale configuration and the prefix policy. Localized URL segments live in `src/lib/i18n/routes.ts`, and every page is generated by `src/lib/game/pages.ts` behind the single catch all route. Do not add a per entity page file.
- Routing identifiers are the bare locale codes. BCP 47 tags appear only at the document boundary, as `fr-FR` and `en-GB` for `lang` and `fr_FR` and `en_GB` for Open Graph. Keep the sitemap locale map consistent with them.
- Keep route locale, document `lang`, Open Graph locale, canonical URL, and alternate language links consistent with one another.
- Every indexable localized page needs a self canonical URL and valid `hreflang` alternates for translations that exist.
- Add `x-default` only when there is a genuine locale neutral destination.
- Do not link to a translation that does not exist.
- French content is the fallback, so an untranslated entry renders in French on an English URL. That is expected and the URL stays indexable.
- Keep UI strings in `src/lib/i18n/strings.ts` rather than inside components.
- Do not concatenate translated sentence fragments. Pass variables into complete messages.
- Use locale aware pluralization, number, date, and list formatting through `Intl`.
- Do not use a country flag as the only language affordance. Keep the locale name as the accessible label.
- Keep stable entity identifiers and the slug strategy consistent across locales, so switching locale lands on the equivalent entity.
- Test locale switching through full document loads and Swup navigation.
