# Code As Documentation

- Explain intent through naming, types, module boundaries, data structures, schemas, and tests.
- Rename unclear symbols instead of explaining them with prose in source files.
- Extract named operations when doing so makes behavior clearer.
- Prefer domain names over implementation names.
- Keep functions small enough that control flow is readable without annotation.
- Prefer discriminated unions and named types over magic values.
- Prefer meaningful constants for shared domain values.
- Make tests communicate behavior through names and fixtures.
- Keep configuration self explanatory through keys, schemas, and file structure.
- Keep APIs unsurprising and consistent with nearby code.
